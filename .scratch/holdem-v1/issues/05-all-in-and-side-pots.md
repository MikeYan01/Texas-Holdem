# 05: All-in 与边池

**What to build:** 有人推光了筹码之后,一切仍然正确。短码 all-in 时,别人多下的部分自动形成他无权争夺的 Side Pot;剩余玩家全部 all-in 后,底牌先亮出来,剩余公共牌一张一张带停顿地发完;每个池子由**有资格争夺它的 Seat 中最强的牌**赢走;打平时底池被平分,不能整除的余数按一条确定规则归属,绝不凭空消失。

这是全项目最容易写错的一票。它也是 6 人桌真正的复杂度所在——正因为如此,当初才选了 6-max 而不是回避它。

**Blocked by:** 04

**Status:** ready-for-agent

- [x] 某个 Seat all-in 且其 Stack 盖不住当前下注额时,超出部分形成 Side Pot,该 Seat 无权争夺
- [x] 一手 Hand 内可以同时存在多个 Side Pot,且顺序与归属正确
- [x] 每个池子(主池与各 Side Pot)**独立结算**,由有资格争夺它的 Seat 中牌力最强者赢走
- [x] 摊牌打平时底池被平分
- [x] 平分产生的余数按确定规则归属:从 Button 左侧起第一个赢家。**总额必须守恒**,余数不得丢弃
- [x] 剩余未弃牌的 Seat 全部 all-in 后,不再有下注轮,剩余公共牌被发完
- [x] 界面在上述情形下先亮出这些 Seat 的底牌,再一张一张带停顿地发出剩余公共牌(节奏由界面控制,引擎不 sleep)
- [x] 界面在存在 Side Pot 时分别显示各个池子的金额
- [x] 界面把已弃牌的 Seat 明显置灰
- [x] 测试直接构造多人不同码量 all-in 的局面,断言最终筹码分配,覆盖:
  - [x] 单个 Side Pot

  - [x] 短码赢下主池但无权争 Side Pot
  - [x] Side Pot 与平分同时发生
  - [x] 余数归属
- [x] 一条守恒断言:任何一手 Hand 结算前后,所有 Seat 的 Stack 之和加上池中筹码保持不变

## Comments

**实现完成。一处显示层的修正:**

引擎的 `state.pots` 是**结算口径**的池子拆分,按每个 Seat 的累计投入切片,这对分池是对的,但直接拿去显示有两个问题:

1. 它把当前 Street 的下注也算进池子,而界面已经把这些筹码画在各自 Seat 面前了——同一笔钱显示两次。
2. 一手牌刚开始、还没人行动时,大盲那一份没被跟的筹码会切出一个只有大盲自己有资格争的池子,于是界面上凭空出现一个「边池 1」。

所以渲染层用 `displayPots(state)`:只拿**已经收进池子的**筹码(`committed - streetCommitted`)去拆,当前 Street 的下注留在 Seat 面前。另外单独显示一个「总计」,方便读底池赔率。真正的边池仍然在有人 all-in、且那条 Street 结束后如实出现。见 `src/engine/selectors.ts`,三条测试钉住了这个行为。

**复盘里补上了「谁有资格争这个池子」**(用户反馈看不懂)。

一手牌出现两个赢家、而且**牌力最大的那个只拿到较小的池子**,在界面上看起来像 bug。真实原因是短码 all-in:你最多只能从每个对手身上赢走自己投入的那么多,超出的部分是别人之间的事。

`pot-awarded` 事件因此多带一个 `eligibleSeats`,复盘面板显示成「主池 81 · 3 人有资格 / 边池 1 610 · 2 人有资格」,悬停有完整规则说明。引擎的结算逻辑一个字没改——它本来就是对的,缺的只是解释。
