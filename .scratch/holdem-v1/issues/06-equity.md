# 06: Equity 计算

**What to build:** 回答"我现在这手牌,赢下这个底池的概率是多少"。这个数字有两个消费者:Bot 用它做决策(第 07 票),Player 在轮到自己时看它学习(第 11 票)。本票只造这个数字本身,不接任何一端。

按 Street 分三段算,不是一律蒙特卡洛(见 ADR-0005):翻牌前查一张自己预生成的表(精确、零耗时);翻牌与转牌蒙特卡洛;河牌样本空间已经小到可以精确枚举。

**Blocked by:** 02 —— 可与 03、04、05 并行

**Status:** ready-for-agent

- [ ] 对外是一个**异步**接口(`await`),即使实现跑在主线程——这样将来挪进 Web Worker 是改一个文件而不是重构
- [ ] 翻牌前:查一张 169 项(规范起手牌)× 对手数的预生成表,精确值
- [ ] 那张表由一个**离线脚本**用本项目自己的求值器生成,产物作为数据提交;脚本一并提交,结果可复现
- [ ] **不得转录任何出自版权书籍的表格**(如 Sklansky-Chubukov、Sklansky 分组)。数字必须是自己算出来的
- [ ] 翻牌与转牌:蒙特卡洛,默认 2000 次迭代
- [ ] 河牌:精确枚举(每个对手 C(44,2) = 946 种可能),不抽样
- [ ] RNG 由外部注入,种子固定时结果完全可复现
- [ ] 蒙特卡洛循环**每次迭代零分配**:扁平 `Int32Array` 牌堆、复用的七槽手牌数组、只抽所需张数的部分 Fisher-Yates
- [ ] 数值验证(允差按迭代次数给出):AA 单挑 ≈85.2%、KK 单挑 ≈82.4%、AKs 单挑 ≈67.0%、AA 六人 ≈49.2%
- [ ] 河牌的精确枚举结果与大量蒙特卡洛的收敛值一致
- [ ] 性能基线:六人底池翻牌前一次 2000 迭代应在数毫秒量级;这条只防数量级退化,不锁死具体数字
- [ ] 位于引擎侧,零运行时依赖

**参考:** `.scratch/poker-eval-reference/eq2.js` 是调查阶段的零分配蒙特卡洛循环,作为写法与性能的参照物,不照搬。
