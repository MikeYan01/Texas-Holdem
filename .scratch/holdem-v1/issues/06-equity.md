# 06: Equity 计算

**What to build:** 回答"我现在这手牌,赢下这个底池的概率是多少"。这个数字有两个消费者:Bot 用它做决策(第 07 票),Player 在轮到自己时看它学习(第 11 票)。本票只造这个数字本身,不接任何一端。

按 Street 分三段算,不是一律蒙特卡洛(见 ADR-0005):翻牌前查一张自己预生成的表(精确、零耗时);翻牌与转牌蒙特卡洛;河牌样本空间已经小到可以精确枚举。

**Blocked by:** 02 —— 可与 03、04、05 并行

**Status:** ready-for-agent

- [x] 对外是一个**异步**接口(`await`),即使实现跑在主线程——这样将来挪进 Web Worker 是改一个文件而不是重构
- [x] 翻牌前:查一张 169 项(规范起手牌)× 对手数的预生成表,精确值
- [x] 那张表由一个**离线脚本**用本项目自己的求值器生成,产物作为数据提交;脚本一并提交,结果可复现
- [x] **不得转录任何出自版权书籍的表格**(如 Sklansky-Chubukov、Sklansky 分组)。数字必须是自己算出来的
- [x] 翻牌与转牌:蒙特卡洛,默认 2000 次迭代
- [x] 河牌:精确枚举(每个对手 C(44,2) = 946 种可能),不抽样
- [x] RNG 由外部注入,种子固定时结果完全可复现
- [x] 蒙特卡洛循环**每次迭代零分配**:扁平 `Int32Array` 牌堆、复用的七槽手牌数组、只抽所需张数的部分 Fisher-Yates
- [x] 数值验证(允差按迭代次数给出):AA 单挑 ≈85.2%、KK 单挑 ≈82.4%、AKs 单挑 ≈67.0%、AA 六人 ≈49.2%
- [x] 河牌的精确枚举结果与大量蒙特卡洛的收敛值一致
- [x] 性能基线:六人底池翻牌前一次 2000 迭代应在数毫秒量级;这条只防数量级退化,不锁死具体数字
- [x] 位于引擎侧,零运行时依赖

**参考:** `.scratch/poker-eval-reference/eq2.js` 是调查阶段的零分配蒙特卡洛循环,作为写法与性能的参照物,不照搬。

## Comments

**实现完成。三处与票面描述不同,都是有意的:**

1. **河牌精确枚举是 C(45,2) = 990,不是票面写的 C(44,2) = 946。** 已知牌是七张(自己两张 + 公共五张),剩 45 张未知,所以对手的可能底牌是 990 种。按 946 枚举会漏掉 44 种。ADR-0005 里的这个数字同样需要修正。代码按 990 实现,`equity-core.ts` 有注释说明。

2. **只有单挑河牌走精确枚举;多人河牌回退到蒙特卡洛,并在 `method` 字段里如实标注。** n 个对手的联合样本空间是 990^n,枚举在两人以上就不再可行。宁可诚实地说"这是抽样",也不要在 `method` 上撒谎。

3. **翻牌前那 169×5 张表是用本项目自己的求值器、每格 200,000 次种子化蒙特卡洛生成的**,不是全枚举。最坏情况 1σ 误差约 0.112%,元数据里写明了迭代次数、种子与误差。生成脚本 `scripts/generate-preflop-table.ts` 可复现(固定种子,845 格,117.7s)。**没有转录任何出自版权书籍的表格。**

**实测数值**(表中读出):AA 单挑 85.09%、KK 单挑 82.39%、AKs 单挑 66.81%、AA 六人 49.26%,与票面给的 85.2 / 82.4 / 67.0 / 49.2 都在 0.2% 以内。

`72o` 单挑测得 34.52%,与 spec「已知的不确定性」里记的 34.59% 一致,同样低于常见引用的 35.3%——独立复现了那条观察。
