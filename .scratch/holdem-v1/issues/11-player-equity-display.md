# 11: Player 的 Equity 显示

**What to build:** 轮到你行动时,界面告诉你当前赢下这手牌的概率。这是这个项目"训练味道"真正落地的地方,而它几乎是白送的——Bot 为了决策本来就要算这个数。

它不评判你的决策,不告诉你"你该弃牌"。那需要一个"正确决策"的基准,而定义正确就是求解器的问题,明确在范围之外。它只给你一个真实的数字,让你慢慢知道 K♠J♠ 在六人底池里到底值多少。

**Blocked by:** 04、06

**Status:** ready-for-agent

- [x] 轮到 Player 行动时,界面显示其当前 Equity
- [x] Equity 随 Street 推进而更新(新公共牌发出后重算)
- [x] Equity 的计算方式随 Street 变化对使用者透明(翻牌前查表、翻牌转牌蒙特卡洛、河牌精确枚举)
- [x] 数字的呈现说明它是"对当前仍在局中的对手数"的胜率,不产生歧义
- [x] 计算不阻塞界面:等待期间有明确的加载态,不出现卡顿或掉帧
- [x] 不显示任何决策建议或对错评价
- [x] 不泄露任何对手的具体底牌信息

## Comments

**实现完成,并按用户反馈扩展:面板的主体从单一胜率改成了「成牌概率」——最终做成每种牌型的概率分布,只显示最高的五种。**

这是一个和 Equity 不同的问题,而且是个更便宜的问题:**「我最后会拿到什么」与对手完全无关**,所以不需要抽样,可以处处精确:

| Street | 方法 | 枚举量 |
| --- | --- | --- |
| 翻牌前 | 查表(离线穷举) | 每手 C(50,5) = 2,118,760 |
| 翻牌 | 现场枚举 | C(47,2) = 1,081 |
| 转牌 | 现场枚举 | 46 |
| 河牌 | 已定型 | 1 |

翻牌前那张表由 `scripts/generate-preflop-hand-odds.ts` 生成:169 个规范起手牌 × 全部 2,118,760 种公共牌,共 3.58 亿次求值,48 秒跑完。**存的是计数不是概率**,所以每格都精确,并且「每行之和恒等于 C(50,5)」是一条可断言的性质。

最强的一条验证:把 169 手按发牌频率(对子 6 组合、同花 4、非同花 12)加权平均,必须复现随机七张牌的公开牌型频次——实测到小数点后三位完全吻合(高牌 17.412%、一对 43.823%、两对 23.496%…)。任何一格算错都会在这里露出来。

接口是**同步**的,与 Equity 的 `await` 不同:最坏情况 1,081 次求值,远低于一毫秒,不需要 Web Worker,假装异步只是徒增仪式。

**胜率没有删掉**,缩成面板右上角的一行——它仍然是 spec 用户故事 30 与 ADR-0005 的核心。如果确认不需要,删掉 `HandOddsReadout` 里那一个 `<span>` 即可。

依然不给任何决策建议:那需要定义「正确打法」,而定义正确是求解器的问题,明确在范围之外。
