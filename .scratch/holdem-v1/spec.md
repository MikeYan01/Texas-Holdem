# 网页版单机德州扑克(v1)

## Problem Statement

我想打德州扑克,但每次都要凑齐人。现成的线上德扑要么是真钱平台(注册、充值、受监管,我完全不想碰),要么是社交游戏(满屏内购、开箱和排行榜)。我想要的只是坐下来打三十手牌,对手不必是真人,打完知道自己赢了还是输了。

顺带地,我想在打的过程中对"这手牌到底值多少"建立一点真实的直觉——现在我只有模糊的感觉。

## Solution

一个跑在浏览器里的单机德州扑克。打开就能开局,不需要账号、不需要联网、没有真钱。

你坐在一张六人桌上,对手是五个性格各异的 Bot。打满五个 Orbit(三十手 Hand),按 Score 排名,结束。

两件事让它比"一个能跑的德扑"更值得打:

1. **轮到你行动时,界面显示你当前的 Equity。** 你会开始知道 K♠J♠ 在六人底池里究竟值多少——这个数字 Bot 本来就要算,给你看一眼是白送的。
2. **每手 Hand 结束后 Reveal:无条件亮出所有 Seat 的底牌,包括早已弃牌的人。** 这是单机局才有的特权,也是学得最快的地方——你会看到自己在 flop 弃掉的牌本来能成顺子,会看到 Maniac 刚才是拿 7♦2♣ 把你诈唬走的。

## User Stories

### 开局与 Session

1. 作为 Player,我想在开始屏点一下就开局,这样我不必做任何配置就能开始打。
2. 作为 Player,我想每个 Session 固定为五个 Orbit(三十手 Hand),这样我一开始就知道这局要花多久。
3. 作为 Player,我想随时看到当前是第几手 Hand、第几个 Orbit,这样我知道还剩多少。
4. 作为 Player,我想在第三十手 Hand 结束后进入结算屏,这样 Session 有明确的终点。
5. 作为 Player,我想在结算屏看到六个 Seat 按 Score 从高到低排名,这样我知道自己打得怎么样。
6. 作为 Player,我想在结算屏一键开新局,这样再打一局不必刷新页面。
7. 作为 Player,我想在关闭或刷新页面时被浏览器拦一下问我确认,这样我不会误手丢掉打了一半的 Session。
8. 作为 Player,我想让刷新之后直接开新局而不是恢复旧局,这样我不必面对一个半吊子的存档。

### 牌桌与位置

9. 作为 Player,我想看到六个 Seat 围成一张俯视的椭圆牌桌,这样它符合我对德扑的心理图像。
10. 作为 Player,我想一眼看到 Button 在哪个 Seat,这样我知道这手牌的行动顺序。
11. 作为 Player,我想看到 Button 在每手 Hand 开始时顺时针移动一位,这样位置优势是轮转的。
12. 作为 Player,我想看到每个 Seat 当前的 Stack,这样我知道谁能下多大注、谁盖不住我。
13. 作为 Player,我想看到 SB 和 BB 在每手 Hand 开始时被强制投入,这样每手牌都有值得争的东西。
14. 作为 Player,我想看到当前轮到行动的 Seat 被明显高亮,这样我不会看丢节奏。
15. 作为 Player,我想看到主池的金额,这样我能判断底池赔率。
16. 作为 Player,我想在存在 Side Pot 时看到它们被分别显示,这样我知道自己在争哪个池子。
17. 作为 Player,我想看到已弃牌的 Seat 被明显置灰,这样我知道还有谁在。

### 发牌与 Street

18. 作为 Player,我想在每手 Hand 开始时看到自己的两张底牌。
19. 作为 Player,我想在整手 Hand 的过程中都看不到任何 Bot 的底牌,这样游戏不被毁掉。
20. 作为 Player,我想看到 flop 三张、turn 一张、river 一张按顺序发出,这样牌局有推进感。
21. 作为 Player,我想让一手 Hand 依次走过 preflop、flop、turn、river 四个 Street。
22. 作为 Player,我想在所有人都弃牌只剩一个 Seat 时立刻结束这手 Hand,不再发无意义的公共牌。

### 我的行动

23. 作为 Player,我想有「弃牌 / 过牌·跟注 / 加注」三个主按钮,这样操作是我熟悉的。
24. 作为 Player,我想让不合法的行动直接不可点(例如无人下注时不能"跟注"),这样我不会试出错误。
25. 作为 Player,我想在加注旁边有「1/2 池」「满池」「All-in」三个预设档位,这样我不必每次心算底池。
26. 作为 Player,我想有一个滑块微调加注额,这样预设档位之外我也能表达。
27. 作为 Player,我想让加注额自动受最小加注规则约束,这样我不会下出不合法的注。
28. 作为 Player,我想在 Stack 不足以完成一次完整加注时仍能 all-in,这样我永远有推的权利。
29. 作为 Player,我不想有任何倒计时,这样我可以想多久想多久。
30. 作为 Player,我想在轮到我行动时看到我当前的 Equity,这样我能逐渐学会牌力到底值多少。

### Bot

31. 作为 Player,我想让每个 Bot 在行动前停顿 600–1200ms 的随机时长,这样我看得清中间发生了什么。
32. 作为 Player,我想在牌桌上看到一条行动记录(例如"Seat 3 加注到 12"),这样我能读懂这手牌的故事。
33. 作为 Player,我想同时面对 TAG、LAG、Calling Station、Rock、Maniac 五种性格,这样牌桌不是一面镜子。
34. 作为 Player,我想让 Bot 在 Pot Odds 划算时跟注,这样它们不会犯我一眼就能看出的蠢错。
35. 作为 Player,我想让 Bot 的下注尺度有变化而不是永远一个数,这样我读不出机械的模式。
36. 作为 Player,我想在打了若干手之后能认出某个 Bot 的行为倾向,这样我可以针对它调整。
37. 作为 Player,我想让 Maniac 偶尔用垃圾牌把我诈唬走,这样牌桌上存在真正的不确定性。

### Showdown 与 Reveal

38. 作为 Player,我想在走完 river 且仍有两人以上未弃牌时看到 Showdown。
39. 作为 Player,我想在剩余玩家全部 all-in 之后,看到他们的底牌先被亮出、然后剩余公共牌一张一张带停顿地发完,这样这个时刻的张力不被浪费。
40. 作为 Player,我想在每手 Hand 结算之后看到 Reveal——所有 Seat 的底牌,包括早已弃牌的人。
41. 作为 Player,我想看到赢家是靠什么牌型赢的,并且用中文表述(例如"两对,A 带 K")。
42. 作为 Player,我想在摊牌打平时看到底池被正确平分。
43. 作为 Player,我想在平分产生不能整除的余数时,看到它按一条确定规则归属某个 Seat,而不是凭空消失。
44. 作为 Player,我想让每个 Side Pot 由有资格争夺它的 Seat 中最强的牌赢走,这样多人 all-in 的结果是对的。

### Stack、Score 与 Rebuy

45. 作为 Player,我想看到每个 Seat 当前的 Score,这样我随时知道排名。
46. 作为 Player,我想让 Score 与 Stack 被清楚区分开显示,这样我不会把"这手能下多少"和"我总共输赢多少"搞混。
47. 作为 Player,我想在任何 Seat 的 Stack 归零时看到它自动 Rebuy 回起始 Stack 并继续打,这样没有人会被踢下桌、干坐着看完剩下的牌。
48. 作为 Player,我想让每次 Rebuy 等额地反映在那个 Seat 的 Score 上,这样排名是诚实的。
49. 作为 Player,我想让六个 Score 之和在任何时刻都恒为零,这样"谁分高"衡量的是真实发生过的转移。
50. 作为 Player,我想在自己破产时也只是 Rebuy 继续打,这样我不会在第八手就出局。

### 动画与可读性

51. 作为 Player,我想看到筹码从 Seat 推向底池的动画,这样我知道钱去了哪里。
52. 作为 Player,我想看到底池在结算时被推向赢家,这样结果是可见的而不是数字突变。
53. 作为 Player,我想看到发牌动画,这样牌局有节奏。
54. 作为 Player,我想让界面文案全部是中文,少数没有通用中文译法的术语(BB、all-in、以及 Bot 的性格名)保留原文。
55. 作为 Player,我想在宽屏 PC 上获得完整体验,不必考虑手机。

### 维护者

56. 作为维护者,我想让引擎是一个零依赖的纯模块(不碰 DOM、window、网络、计时器),这样我能在 Node 里跑十万手 Hand 验证零和不变量。
57. 作为维护者,我想让引擎是对一个显式 state 值的纯 reducer,这样测试可以从任意局面开始,而不必先把牌打到那儿。
58. 作为维护者,我想让随机源可注入,这样每一个失败的测试都能被原样复现。
59. 作为维护者,我想让求值器被全部 133,784,560 手牌穷举验证过,这样我信任它。
60. 作为维护者,我想让引擎不含任何用户可见文案、只吐结构化事件,这样界面语言与引擎彻底解耦。
61. 作为维护者,我想让 Equity 藏在异步接口之后,这样将来要挪进 Web Worker 是改一个文件而不是重构。
62. 作为维护者,我想让下注金额的计算(预设档位、最小加注、all-in 上限)全部在引擎里,这样它落在测试缝之内而不是组件里。

## Implementation Decisions

### 模块与缝

三个被测模块,对应三条测试缝(已与用户确认):

**`poker-math`** —— 纯计算,无状态。

- `evaluate7(cards)` 接受七张牌,返回**单个可比较的整数**。相等即意味着平分底池。不返回"类别 + 踢脚数组",因为那会迫使每个调用点自己写比较逻辑,而分池 bug 正是在那里滋生的(ADR-0004)。大小方向必须在接口上写死,并有测试固定。
- `equity(hole, board, opponentCount, rng)` 按 Street 分三段(ADR-0005):翻牌前查预生成表;翻牌与转牌蒙特卡洛 2000 次;河牌精确枚举 C(44,2)=946。
- 翻牌前那张 169 项的表由一个**离线脚本**用本模块自己的求值器生成,产物作为数据提交。不得转录任何出自版权书籍的表格。
- 蒙特卡洛循环必须**每次迭代零分配**:扁平 `Int32Array` 牌堆、复用的七槽手牌数组、只抽所需张数的部分 Fisher-Yates。实测 0.72 µs/次里这套纪律占了大半。

**`engine`** —— 纯状态机,零依赖。

- `createSession(config)` 返回初始 state;`reduce(state, action)` 返回新 state。二者都是纯函数。
- **引擎从不 sleep、从不使用计时器。** Bot 的思考延迟和发牌节奏由 UI 决定何时投递下一个 action;引擎只回答"给定当前 state 和这个 action,下一个 state 是什么"。这是 ADR-0001 的直接后果。
- state 是显式且可构造的:Seat 列表(含 Stack、Score、是否弃牌、是否 all-in)、Button 位置、当前 Street、公共牌、主池与 Side Pot 列表、当前行动者、牌堆、Hand 序号、Orbit 序号。测试可以直接写一个 state 字面量。
- **合法行动由引擎计算并挂在 state 上**,UI 只按它启用/禁用按钮。最小加注额、跟注额、all-in 上限、三个预设档位的具体金额,全部由引擎算好给出。
- 引擎**只吐结构化事件**(行动、发牌、底池变动、结算),不吐任何文案。中文由渲染层翻译(见 `AGENTS.md`)。
- RNG 由外部注入,签名是返回 `[0,1)` 的无参函数。引擎内不得出现 `Math.random`。
- Bot 策略作为依赖注入,引擎自身不 import 任何具体策略。

**`bots`** —— 纯决策函数。

- `decide(view, personality)` 返回一个 action。`view` 是从引擎 state 派生的、只含该 Seat 可见信息的投影——**它在类型上就不应包含别人的底牌**,让作弊成为类型错误而不是纪律问题。
- 决策规则(ADR-0003):算出 Equity,与 Pot Odds(`跟注额 ÷ (底池 + 跟注额)`)比较。低于则弃牌;高于则跟注;高出足够余量则加注。
- 五种性格是加在这个比较上的**常数偏移**,不是五套逻辑:门槛高低(松/紧)、升级为加注所需的余量(被动/激进)、翻牌前入池范围宽窄。
- Bot 不使用**真实** Equity:必须叠加每个 Bot 自己的噪声,否则它们会跟注过多且显得机械。这同时让 2000 次抽样的误差变得无害。

**UI** —— React,只订阅引擎状态,不含规则逻辑,不做组件测试。

### 关键规则契约

- **Side Pot**:任何 Seat all-in 且其 Stack 盖不住当前下注额时,超出的部分形成新的池子,该 Seat 无权争夺。一手 Hand 内可同时存在多个 Side Pot。每个池子由**有资格争夺它的 Seat 中最强的牌**赢走,逐池独立结算。
- **平分余数**:摊牌打平且底池不能整除时,余数按一条确定规则归属(从 Button 左侧起第一个赢家),不得丢弃。
- **Rebuy**:Stack 归零即自动补回起始 Stack;Stack 增加多少,该 Seat 的 Score 就减少多少。不设次数上限,无人离桌。
- **零和不变量**:任意时刻六个 Score 之和恒为 0。这是引擎最重要的一条性质。
- **Session 终止**:第三十手 Hand 结算完毕即结束,不因任何 Seat 破产而提前结束。
- **牌局参数**:SB 1 / BB 2,全程不涨;起始 Stack 200(即 100 BB);六个 Seat,一个 Player 五个 Bot,座位随机。

### 技术栈

TypeScript + Vite + React,测试用 Vitest,产物是静态站点。`phe` 只作为 **dev 依赖**用于差分测试,不进运行时。

## Testing Decisions

### 什么算一个好测试

只测**外部行为**,不测实现细节。对本项目具体意味着:

- 断言"三人 all-in 且码量不同时筹码如何分配",而不是"某个内部函数被调用了几次"。
- 断言"底池 100、跟注 2、Equity 30% 的 Bot 不会弃牌",而不是"它内部算出的阈值是 0.0196"。
- 测试不读取也不断言 state 里的私有中间量;只有从 state 的公开形状和引擎吐出的事件上能观察到的,才算行为。
- 每个失败必须可复现:所有涉及随机的测试都注入种子化 RNG。

### 缝 1:`poker-math`

- **穷举验证**:枚举全部 C(52,7) = 133,784,560 手牌,统计九个牌型频次并与公开值比对(约 37 秒)。这条必须进 CI——它是"自己写求值器"这个决定的全部依据。
- **差分测试**:与 `phe` 跑数十万次随机对局排序与摊牌平局判定,断言零分歧。
- **陷阱用例**:ADR-0004 列出的九个陷阱各一条显式测试——同花且有顺子不等于同花顺、A-2-3-4-5 轮子、轮子同花顺、A 不回绕、两组三条构成葫芦、七张牌三个对子时踢脚可能是第三对、四条踢脚来自对子、六七张同花取最大五张、相等即分池。
- **Equity 数值验证**:AA 单挑 ≈85.2%、KK ≈82.4%、AKs ≈67.0%、AA 六人 ≈49.2%,允差按迭代次数给出。
- **性能基线**:一条不追求精确、只防止数量级退化的基准断言。

**Prior art**:`.scratch/poker-eval-reference/` 有四个来自调查阶段的参考脚本(`myeval.js`、`exhaustive.js`、`headtohead.js`、`eq2.js`)及其 README。它们是**正确性的参照物与性能基线,不是要照搬进 `src/` 的代码**——实现走 TDD 重写。

### 缝 2:`engine`

引擎测试**注入脚本化策略**("永远跟注"、"第 3 个 Seat 在 flop 加注满池"),不使用真 Bot,这样规则的测试不被 Bot 的随机性污染。

因为引擎是对显式 state 的纯 reducer,测试**直接构造起始局面**,不必把牌打到那儿。覆盖:

- 下注轮的推进与终止(何时进入下一个 Street、谁重开了下注权)。
- 最小加注、跟注额、all-in 上限、三个预设档位的金额计算。
- Side Pot 的形成与逐池结算,包括多个 Side Pot 并存。
- 平分底池与余数归属。
- 只剩一人未弃牌时立即结算,不再发牌。
- 全员 all-in 后剩余公共牌的发出。
- Button 移动、盲注归属、Position 轮转。
- Rebuy 的触发与 Score 的等额扣减。
- Session 在第三十手 Hand 后终止。
- **属性测试**:注入种子化 RNG 与随机合法行动,跑十万手 Hand,每手结束断言六个 Score 之和为 0、所有 Stack 非负、底池总额守恒。这条是引擎的主验证手段。

### 缝 3:`bots`

- **Pot Odds 属性**:构造底池远大于跟注额的 view,断言任何性格的 Bot 都不弃牌——这是 ADR-0003 存在的全部理由。
- **性格排序**:同一个 view 下,Rock 的入池率必须低于 Calling Station,Maniac 的加注率必须高于 TAG。断言的是**相对次序**而不是具体数字,否则测试会锁死调参。
- **决策合法性**:对大量随机 view,断言返回的 action 永远是引擎认可的合法行动之一。
- **视野封闭**:类型层面保证 `view` 不含其他 Seat 的底牌;辅以一条测试确认从 view 构造不出这个信息。

## Out of Scope

- 真钱、充值、提现、任何形式的支付
- 真人对战、联机、房间、匹配
- 后端、账号、登录、云端存档
- 锦标赛结构:涨盲、淘汰、名次奖励、多桌平衡
- 求解器级 AI(CFR、手牌抽象、对手范围建模)
- 复盘建议("你这手该弃牌")与决策评分
- 重放某一 Session
- 跨 Session 的长期统计与成就
- 难度选择、Bot 阵容自定义
- 移动端与响应式布局
- 音效
- 德扑之外的变体(奥马哈、短牌)与其它下注结构(限注、底池限注)
- 行动倒计时
- 中途存档与断线恢复

## Further Notes

### 相关 ADR

本 spec 的每条重要约束都有对应的 ADR。实现时若想推翻其中任何一条,请先读它:

- **ADR-0001** 无后端,引擎是零依赖纯模块
- **ADR-0002** Stack 与 Score 是两个不同的概念
- **ADR-0003** Bot 用底池赔率决策,不做求解器
- **ADR-0004** 自己写求值器,`phe` 仅作 dev 差分对照
- **ADR-0005** Equity 分三段计算

术语一律以 `CONTEXT.md` 为准。尤其注意 **Street / Hand / Orbit / Session** 四者在中文里都会被叫成"一轮",以及 **Showdown**(牌局规则)与 **Reveal**(我们额外加的学习环节)不是一回事。

### 已知的不确定性

- 所有性能数字实测于 Node v26.7 / Apple M3 Pro,**未在真实浏览器中验证过**。V8 与 Chrome 同源,但 Safari/Firefox 是不同引擎,而这段代码高度依赖 typed array。首个可玩版本出来后应当在目标浏览器里实测一次。
- 调查阶段测得 `72o` 单挑 34.59%,而常见引用值约 35.3%。其余六个验证点都吻合在 0.3% 以内,倾向于是参考值对"随机对手"的定义不同。若某处依赖这个数,需要重新核对。

### 实现顺序的建议

`poker-math` 没有任何上游依赖,而它的正确性是其余一切的地基——先做它,并且让那条穷举验证第一天就跑起来。引擎次之(用脚本化策略即可完整测试,不需要真 Bot)。Bot 依赖 `poker-math` 的 Equity 与引擎的 view 类型。UI 最后。
