# Hand Odds are separate from Equity, and exact at every Street

The **only** number the interface puts in front of the Player is **Hand Odds**: the probability distribution over the hand category the Hand will finish as, of which only the top five are shown. **Equity is not displayed**; it is kept for Bot decisions.

The two answer different questions, and Equity is by far the more expensive:

- Equity asks "am I going to win", which means dealing the opponents in, so it can only be sampled (ADR-0005).
- Hand Odds asks only "what am I going to end up holding", which is **entirely independent of the opponents**, so it can be enumerated exactly everywhere.

| Street | Method | Enumeration |
| --- | --- | --- |
| Preflop | Table lookup (exhaustive, offline) | C(50,5) = 2,118,760 per starting hand |
| Flop | Enumerated live | C(47,2) = 1,081 |
| Turn | Enumerated live | 46 |
| River | Already determined | 1 |

The preflop table is generated by `scripts/generate-preflop-hand-odds.ts`: 169 canonical starting hands × every community-card combination, 358 million evaluations, 48 seconds. **What is stored is counts, not probabilities**, so every cell is exact and "every row sums to exactly C(50,5)" is a property you can assert.

## Considered Options

**Show Equity only (the original approach).** Rejected: a bare 28% tells you nothing. "Pair 45.9% / Two pair 22.8% / High card 19.5% / Three of a kind 4.5% / Straight 3.1%" tells you what this Hand **is going to turn into**, which is precisely the intuition a beginner needs to build — a flush shows up on the list only when you really do have a flush to make, and that alone is teaching the game.

**Show all nine hand categories.** Rejected: nine rows is more than anyone reads, and the ones at the tail are usually of the order of 0.03%. Take the top five, and **drop the zero-probability categories** rather than listing them as 0%.

**Compute it by Monte Carlo, sharing one loop with Equity.** Rejected: from the flop on, the sample space is small enough that enumeration is faster, and sampling only adds noise. This number does not need error bars.

**Make the interface async, for consistency with `getEquity`.** Rejected: the worst case is 1,081 evaluations, far under a millisecond, and it will never need a Web Worker. Pretending it is async only makes every call site carry an extra `await`.

## Consequences

One more piece of generated data, 17 KB (counts take more room than probabilities), in exchange for a preflop answer that is exact and costs nothing.

The strongest validation of the lot came for free: average the 169 starting hands weighted by how often they are dealt, and the result has to reproduce the published hand-category frequencies for seven random cards — measured, it matches to three decimal places exactly (Pair 43.823%, Two pair 23.496%…). Any cell computed wrong is exposed here, and the check runs in a few milliseconds.

The Equity **computation** was not deleted; the whole of ADR-0003's Bot decision logic rests on it. What was deleted is its display, and with it the redundant computation that ran whenever the action reached the Player.
